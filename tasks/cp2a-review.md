## Frozen implementation decisions

- T19 is additive pure content generation, not a new browser database or save migration. Shared case identities key on `(contentVersion, campaignSeed, caseId)`; local decoys key on the unchanged normative `missionRng(seed, missionId, variant)`. Replaying a different mission must not change shared people/vehicle/times. Explicit stable sorting precedes random selection. Only trusted fixed schema identifiers and parameterized values are emitted.
- Mission manifest v1 explicitly carries case/content/seed versions, full comparison/constraint/evidence/h4 metadata. `variants.sql` uses unique `-- variant: <id>` blocks; generated references are `variants/<id>.sql`. Exactly one reference plus at least two independent variants, three wrong fixtures and four hint keys per playable mission. Independence is editorial + later PG fixtures, never inferred from whitespace or seed count. No current mission is playable.
- `x_*` extension keys are rejected for now (closed schema); future extensions require a documented versioned schema amendment. Constraints use finite named predicates, never evaluated expressions. Paths are narrow ASCII relative SQL paths, no traversal/URLs/encoded separators.
- Season outline records all 80 objectives and acts, separate from the empty playable registry. Synthetic validation packs live only in test fixtures, not public assets. Future reference execution remains T22–T27; `test:fixtures` must still fail clearly until then.
- Graph contracts are pure, runtime-independent. Proof paths carry declared source IDs and reasoning IDs, require three distinct independently reachable paths, and explicitly state resolution policy. Optional-clue removal tests both surviving-route robustness and actual resolution feasibility. Progression simulation uses distinct assessed item IDs and actual taught/story/familiar gates, including fixed A1/A2 spine and rest-after-spike checks; it is validation, not the T28/T29 runtime service.
